# Contributing Guide

Thanks for contributing! Please follow these conventions — real open source
projects will reject PRs that ignore theirs, so treat this as practice for that.

## Before you start
- Fork this repository to your own account.
- Clone **your fork** locally (not the original repo).
- Add the original repository as a remote named `upstream`.

## Branch naming
All branches must follow this pattern:

```
<type>/<short-description>
```

Where `<type>` is one of: `feature`, `fix`, `docs`, `chore`.

Example: `docs/add-my-name`

## Commit messages
Follow the [Conventional Commits](https://www.conventionalcommits.org/) style:

```
<type>: <short summary>

<optional longer description>
```

Example:
```
docs: add name to contributors list
```

## Opening a Pull Request
- Push your branch to **your fork**.
- Open a PR from your fork's branch into this repo's `main` branch.
- Fill out the PR template completely — don't delete sections.
- Link the related task/issue in your PR description.
- Make sure `QUESTIONS.md` is fully answered and included in your PR.

## Code review
- A mentor will review your PR and may request changes.
- Please respond to comments instead of opening a new PR.
- Once approved, your PR will be merged (or you may be asked to merge it yourself, depending on your program's setup).

## Code of conduct
Be respectful, patient, and kind — the same standard expected on any real
open source project.
